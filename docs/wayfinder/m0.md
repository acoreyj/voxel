# Wayfinder snapshot — M0 through the v4 voxel engine contract

_Local snapshot taken 2026-10-09. The live, canonical map is GitHub issue #1: https://github.com/acoreyj/voxel/issues/1 . This file mirrors it for durability; if they disagree, the issue is canonical._

## Destination

An M0 that is **decision-complete**: every open decision gating the M0 vertical slice (generate → mesh → commit → collide) and the §3.2/3.3/3.4 concurrency-and-streaming contract is resolved, with nothing left to decide before implementation. Later milestones (M1–M5) are out of scope; the frontier stops at M0.

## Notes

- **Spec:** the normative spec is `voxel-design-doc.md` (v4); rationale and rejected alternatives are in `voxel-decision-log.md`. If they disagree, the design doc wins.
- **Decisions only.** This map resolves decisions; it does not build. M0 implementation is a separate effort once the frontier empties.
- **Vocabulary:** see `docs/agents/domain.md`; terms are used as in the design doc (cell, sample, core block, mesh window, edit phase).
- **Tracker:** GitHub. Tickets are child issues; blocking uses native dependencies. One ticket per session (research excepted).
- **Targets:** §7.3 numbers are stated against the reference hardware, recorded by a ticket here; until then they are targets, not commitments.
- **Known-stale spec sections** (decisions contradict the doc; the doc is *not* edited by this map): §6.2/§6.3 (Godot 4.2 → 4.7), §4.5 (`map_get_iteration_id` → per-region `region_get_iteration_id`; `INavServerSync` baseline ownership), §6.1 (C++20 is required for `std::span`, not `std::atomic::wait`; Windows CRT chosen `/MT`, not `/MD`).

## Decisions so far

- [Survey Godot 4.2 vs 4.7 for the engine's needs](https://github.com/acoreyj/voxel/issues/2): 4.2 fails the design's own §4.5 (needs `map_get_iteration_id`, 4.3+). Research: branch `research/godot-version`.
- [Choose the pinned Godot and godot-cpp target version](https://github.com/acoreyj/voxel/issues/9): **Godot 4.7 + Forward+**; godot-cpp `10.0.0-stable` (`507ed9d8`) at `api_version=4.7`; `compatibility_minimum = "4.7"`; adapt the existing project and strip `.NET`; nav async path kept.
- [Verify the RenderingServer surface and material-channel API at the pinned godot-cpp](https://github.com/acoreyj/voxel/issues/10): no raw attribute-view overload exists; use `mesh_add_surface_from_arrays` with `ARRAY_CUSTOM0`/`RGBA8_UNORM` for the per-vertex material channel; `ConcavePolygonShape3D.set_faces` takes a flat soup; there is **no** fast-parse setting. Branch `research/rendering-surface`.
- [Verify the NavigationServer3D bake/sync API at the pinned Godot version](https://github.com/acoreyj/voxel/issues/11): `bake_from_source_geometry_data_async` is genuinely async; synchronize with `region_get_iteration_id` + `is_baking_navigation_mesh`, **not** `map_get_iteration_id`, and `map_force_update` is deprecated at 4.7. Corrects `INavServerSync`: `submitted_region_iteration`, wrapper owns per-key baselines. Branch `research/nav-api`.
- [Pin the remaining toolchain: compiler, C++ standard, FastNoise2, LZ4](https://github.com/acoreyj/voxel/issues/12): **C++20** (forced by `std::span`, not `std::atomic::wait`); MSVC v143+ / Clang 15+ / GCC 11+; Windows CRT must be force-set **before** `add_subdirectory(godot-cpp)`; FastNoise2 **v1.1.1** (M1-conditional, `FASTNOISE2_STRICT_FP=ON`); LZ4 **v1.10.0** vendored. Branch `research/toolchain-pin`.
- [Fix the M0 module, build, and dependency layout](https://github.com/acoreyj/voxel/issues/5): `src/core` + `src/godot` + `thirdparty` submodules in one CMake graph; `kChunkSize` via CMake option `VOXEL_CHUNK_SIZE` (default 32), tested at 32/16; deps = `ankerl::unordered_dense`, bounded mutex MPSC ring, injectable `IMemoryLedger` + `BlockAllocator` slab; **doctest** + `VOXEL_ASSERT`/`VERIFY` + atomic telemetry; Windows CRT **`/MT`/`/MTd`**; CI matrix Clang (UBSan/ASan/TSan) + GCC + N∈{32,16} + Windows MSVC link smoke.
